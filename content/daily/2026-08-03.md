一、Portfolio User App 请假模块深度熟悉

**项目背景**：校园学生服务平台的 uni-app（Vue 3 + TS）学生/家长端，请假线是核心业务模块。

**模块架构分析**：

| 层级 | 核心文件 | 职责 |
|------|---------|------|
| 类型定义 | `types/enums.ts` / `types/models.ts` | LeaveStatus（6态）、LeaveType、ApprovalLevel、DTO |
| 业务规则 | `features/leave/rules.ts` | 7条纯函数规则（在途上限/重叠/审批级别/可取消/可销假/改期/逾期） |
| 状态机 | `features/leave/status.ts` | 审批链生成、按角色推导状态、节点推进、销假/逾期提醒 |
| 展示层 | `features/leave/display.ts` | 状态配色、筛选分组、审批时间线文案 |
| API | `api/leave.ts` | 8个接口（CRUD + 改期 + 销假 + 班级查询 + 开发用推进审批） |
| Mock | `mocks/leave.ts` | 有状态 mock，复用 rules/status 纯函数做双重校验 |
| 页面 | `pages-sub/leave/` | select → create → query → detail → class-query |

**设计亮点**：
- **状态机驱动**：Pending → Reviewing → Approved → Completed，审批链按时长自动分级（≤3天辅导员一级，3~7天辅导员+书记两级，>7天不受理）
- **改期 = 重新申请**：按新时长重新推导审批级别，审批链追加而非替换（历史保留）
- **双重防线**：前端 rules.ts + mock/后端 复用同一套纯函数校验
- **类型级隐私**：ClassLeaveItem 在类型层面不包含 reason/attachments，学委视角从 TS 层面就无法访问隐私字段
- **Mock 模拟真实环境**：6秒自动推进审批节点、逾期扫描、提醒去重

**逻辑严谨性评估**：识别了 5 个可增强点：
1. Approved 假条无法取消（开始时间未到时可考虑开放取消窗口）
2. 逾期假条仍可延长（canExtend 应增加逾期判断）
3. Reviewing 态无操作入口（可增加催办提示）
4. 多次改期审批链无限增长（可折叠历史轮次）
5. Role.Secretary 枚举缺失（用 Admin 占位，已知技术债）
